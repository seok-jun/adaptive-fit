# 운동 중 입력을 줄이는 기록과 코칭

## 첫 사용자 요구
운동하는 사람은 세트마다 기구·무게·반복 수를 다시 적지 않고 실제 수행을 기록하고 싶다. 처음에는 기구를 촬영하거나 운동을 직접 선택하고 필요한 수치를 입력한다. 이후에는 기존 기록을 활용한 AI 코칭 제안을 보고 그대로 수행하거나 원하는 값으로 조절할 수 있어야 한다. 세트가 끝나면 수행 여부와 실제 반복 횟수(reps)를 최소한의 조작으로 남긴다.

## 첫 성공 장면
이미 한 세트를 기록한 운동에서 오늘 프로그램에 있는 다음 세트의 예정 무게와 횟수를 확인한다. 사용자는 기구나 기본 수치를 처음부터 다시 입력하지 않는다. 제안과 실제 결과가 달라도 실제 반복 횟수를 선택해 남길 수 있다. 제안을 보거나 수정하는 동작만으로 세트를 수행한 것으로 기록하지 않는다.

## 세트 기록 동작
- 추천 횟수와 같은 횟수 버튼을 한 번 누르면 해당 무게와 실제 횟수로 세트 한 건이 기록된다. 별도 완료나 확인 동작은 없다.
- 추천과 다르면 실제로 한 횟수를 누르는 것으로 세트 기록이 끝난다. 추천 횟수가 실제 수행값을 덮어쓰지 않는다.
- 무게는 제안된 값을 기본으로 표시한다. 사용자가 무게를 바꾼 경우에만 그 세트의 무게를 수정하며, 실제 횟수를 누르면 수정한 무게와 선택한 횟수가 함께 기록된다. 무게 수정만으로 세트를 완료하지 않는다.

| 제안 | 실제 수행 | 필요한 조작 | 저장 결과 |
| --- | --- | --- | --- |
| 100kg × 8회 | 100kg × 8회 | 8회 한 번 | 100kg × 8회 한 세트 |
| 100kg × 8회 | 100kg × 7회 | 7회 한 번 | 100kg × 7회 한 세트 |
| 100kg × 8회 | 95kg × 7회 | 무게를 95kg으로 수정 후 7회 선택 | 95kg × 7회 한 세트 |

## 마지막 몇 회만 구간 반복한 세트
- 일반 세트는 횟수 버튼 한 번으로 기록한다. 구간 반복 여부를 매번 묻지 않는다.
- 필요한 세트에서만 구간 반복 옵션으로 마지막 몇 회를 구간 반복했는지 선택할 수 있다. 예를 들어 총 15회 중 마지막 5회를 선택하면 전 구간 10회와 구간 반복 5회인 세트 한 건으로 저장한다. 구간 반복 횟수는 총횟수를 넘을 수 없다. 다음 세트는 다시 일반 입력으로 시작한다.
- AI가 같은 무게의 두 세트를 비교할 때 전 구간 15회와 총 15회 중 마지막 5회 구간 반복을 구분한다. 웨이트를 마친 뒤 해당 운동의 피드백에 실제 수행 방식을 반영한다. 구간 반복이라는 사실만으로 그 이유를 추정하지 않는다.

## 피드백의 기준
사용자는 감량·근비대·유지와 같은 운동 목표를 선택한다. AI는 운동 종류별·일간·주간·월간 피드백에서 선택한 목표에 맞춰 실제 운동 기록과 관련 신체 변화 기록을 해석한다. 예를 들어 같은 웨이트 기록이라도 감량 목표에서는 감량 기간 중 운동 수행의 변화, 근비대 목표에서는 훈련량과 반복 수행의 변화, 유지 목표에서는 평소 수준의 안정성에 초점을 둔다. 체중이나 근육량의 실제 변화는 운동 기록만으로 단정하지 않는다. 세 목표는 확인된 예시이며 전체 목록은 열려 있다.

## 피드백을 받는 시점
- 운동 종류별 피드백: 웨이트를 마치면 그날 수행한 웨이트 기록을 바탕으로 피드백을 받는다. 같은 날 다른 종류의 운동을 이어서 하면 그 운동을 마친 시점에 해당 운동의 피드백을 따로 받는다. 웨이트 한 종목이나 한 세트의 종료는 웨이트 전체의 종료가 아니다.
- 하루 피드백: 그날 수행한 운동들을 함께 돌아본다.
- 주간·월간 피드백: 각각 일주일과 한 달에 걸친 운동 기록을 함께 돌아본다. 각 요약의 상세 지표, 기간 경계와 전달 방식은 미정이다.

## 이어지는 제품 목표
앱 안에서 기록을 근거로 AI에게 질문하고, 운동 종류별 종료와 하루·주·월 단위로 AI 피드백을 받으며, 필요할 때 프로그램을 조정하고 신체 변화도 추적한다.

## Android 개발 환경

첫 실행 대상은 Android다. JDK 17, Android SDK Platform 36, Build Tools 36.0.0, Platform Tools를 설치하고 각각 JAVA_HOME과 ANDROID_HOME을 지정한다. Windows에서는 저장소 루트에서 다음 명령으로 컴파일·단위 테스트·lint·APK·앱 번들을 검증한다. Gradle wrapper가 Gradle 9.9.3을 사용한다.

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:lintDebug :app:assembleDebug :app:bundleRelease
```

Android Studio의 Device Manager에서 API 36 에뮬레이터를 시작한 뒤 설치하고 첫 화면의 Adaptive Fit을 확인한다. 여러 기기가 연결돼 있다면 adb에 대상 기기의 -s 옵션을 지정한다.

```powershell
.\gradlew.bat :app:installDebug
& "$env:ANDROID_HOME/platform-tools/adb.exe" shell am start -W -n org.adaptivefit.mobile/.MainActivity
```

debug APK는 app/build/outputs/apk/debug/app-debug.apk, release AAB는 app/build/outputs/bundle/release/app-release.aab에 생성된다. release AAB에는 배포용 서명이 설정되어 있지 않다.

# 첫 코칭의 목표와 수용 조건

기준은 01-as-is.md (0fca69a), #2 및 docs/product-direction.md. 앱 시작 시 마지막 승인 계획과 코치 설정을 복원한다. 사용자가 목표, 시간, 기구를 고르고 코칭을 요청한다.

- D1. 개인 키는 공급자별 SecureStore 항목으로 등록·교체·삭제한다. 원문을 화면에 다시 채우거나 SQLite·로그·번들에 기록하지 않는다. 비밀·운동 데이터 백업을 끄고 개인 설치용으로 서명한다.
- D2. 공급자, 모델, 강도 선택을 SQLite에 저장한다. 각 공급자에서 두 가지 이상 모델을 제공한다. 기능표에 있는 조합만 허용하고 기본 강도는 필드를 생략한다. 타 공급자로 자동 전환하지 않는다.
- D3. 매 요청 직전 공급자·모델과 전송할 목표·시간·장비, 개인 계정의 과금 가능성을 표시하고 전송 버튼을 받아야 한다. 사용자 입력 정보는 세 항목만 사용한다. 고정된 공급자 URL에만 해당 키를 보내고 중복 전송 버튼을 막는다. 자동 재시도하지 않는다.
- D4. AI가 운동 ID, 분 단위 소요 시간, 한국어 이유와 지침을 제안한다. 허용 종목표에서 장비가 맞고 총 시간이 예산 이내여야 한다. 잘못된 응답·API 실패는 현재 승인 계획에 영향을 주지 않는다. 성공한 초안은 승인 버튼을 누를 때만 SQLite의 마지막 계획으로 원자적으로 교체한다. 앱 재시작 시 미승인 초안은 폐기한다.
- D5. 로컬 서명 release APK에 JS를 내장한다. APK·서명 자격증명은 Git에 게시하지 않는다. 자동 검증은 합성 데이터와 가짜 키로 수행한다. 개인 폰은 사용자가 설치 후 자기 계정으로 검증한다.

AC1 키 등록·교체·삭제와 옵션 복원. AC2 승인 전 외부 호출 0건, 승인 후 선택 대상에 1건. AC3 기구/시간/구조 오류 또는 API 오류 시 승인 계획 유지. AC4 유효 제안의 승인 후 재실행 복원. AC5 서명·패키지·JS 내장과 개발 서버 없는 Android 실행 확인.
